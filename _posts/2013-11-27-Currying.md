Currying is the technique of transforming a function that takes multiple arguments into a chain of functions each taking a single argument.

Consider this simple function to add two arguments.

```
plus = function(x, y) {
	return x + y;
};

plus(2, 3); //=> 5
```

```
plus1 = function(x) {
	return function(y) {
		return x + y;
	};
};

plus1(2)(3); //=> 5

add2 = plus1(2); //=> function
add2(3); //=> 5

plus(2, 3) == plus1(2)(3) //=> true
```

In above example, `plus1` is the curried form of `plus`.

### Motivation

Currying is similar to the process of calculating a function of multiple variables on paper. For example, given the function `f(x, y) = x + y`, to evaluate f(2, 3), first we replace x with 2 to get `f(2, y) = 2 + y `. The result is a function of y, and can be defined as `g(y) = f(2, y) = 2 + y`. Now replace y with 3, producing `g(3) = f(2, 3) = 2 + 3 = 5`.

On paper, using classical notation, each argument can be replaced sequentially. Each replacement results in a function taking exactly one argument. This produces a chain of one-argument functions, and multi-argument functions can be represented in curried form. Haskell always uses curried functions.

### How is it related to partial function application

When a function takes multiple arguments, we “apply” the function to the arguments by evaluating it with all of the arguments, producing a value. But what if we only supply some of the arguments? In that case, we can’t get the final value, but we can get a function that represents _part_ of our application.

Consider the simple addition function:

```
add = function(x, y) {
	return x + y;
};
```

This code implements a partial application of add function by binding one variable in advance:

```
add5 = function(x) {
	return add(x, 5);
};
```

### Native support

Curried functions do add the overhead of partial application and closure creation. So generally uncurried functions are preferred unless language provides native support for currying.

Haskell has currying built into the language. Every function in Haskell officially only takes one parameter. Consider the `max` function. It looks like it takes two parameters and returns the one that's bigger. Doing max 4 5 first creates a function that takes a parameter and returns either 4 or that parameter, depending on which is bigger. Then, 5 is applied to that function and that function produces our desired result. The following two calls are equivalent:

```
> max 4 5 
5
> (max 4) 5
5
```

As with currying, in fact, _because_ of currying, partial application is also built into Haskell. If you call a function with too few parameters, we get back a partially applied function, meaning a function that takes as many parameters as we left out. Using partial application is a neat way to create functions on the fly so we can pass them to another function or to seed them with some data.  

### Notation

```
plus:(x,y)->z = curry(plus):x->y->z
```
`plus` is a function that takes 2 arguments x & y and returns z.  
Currying it makes a function that takes x and returns a function of type y->z. Expanding further,  
Currying it makes a function that takes x and returns a function that takes y and returns z.  

-> is right associative. x->y->z = x->(y->z)
